## How to use it
- **Writer:** read this catalogue and the hub exemplar (`specs/<dir>/_exemplar.md`) before writing, then run QC until TOTAL 0. Writers do not self-score. On rework, fix the class, not the instance: search the whole page for every occurrence of the defect in the note.
- **Reviewer and challenger:** read the page cold, then verify earlier fixes. Every finding is a rule violation: it names the rubric criterion, cites the HUB_RULES section or the row above it breaks, quotes the field, and is marked `blocking` or `note` (`hubctl review` and `hubctl challenge` reject findings without a cited rule). Repeated ideas (#21) are blocking; an unsourced statement of fact about the world is blocking, an unsourced recommendation is a note. Only blocking findings send a page to rework, and rework fixes blocking findings only; notes are kept in `spec.review_notes`, and a note that recurs on 3+ pages is proposed to Divit as a rule (`hubctl metrics`).
- **Divit's rejections:** add a row here the same day, and a QC check if the defect can be measured.
